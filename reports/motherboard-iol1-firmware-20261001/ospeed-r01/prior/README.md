# Four fitted-node read-only prototype firmware

This is a separate diagnostic image for actual STM32G031C8T6 DIC/ACC and STM32G031K8T6 DOA/DOB parts. It uses the four existing IOL1 lanes and the reviewed four PB5/TIM3_CH2 count taps. It does not implement the commercial commissioning, configuration, output-authority or bootloader application.

Each image boots at main Flash address `0x08000000`, uses HSI/PLL at nominal64MHz, hardware-NSS SPI1 mode0 and two DMA channels. Acceptance requires CS HIGH, no DMA/SPI error, both40-byte DMA completions, exactly320 observed TIM3 clock edges, header/class/fixed physical slot, nonzero epoch, sequence, read-only policy and CRC-32C. Only acceptance reloads IWDG after its initial startup load. Duplicate SYNC, partial trailing clocks, invalid/reserved commands, payload writes and stale sequence do not refresh it. The counted IWDG period is1.176–1.356ms from the published LSI limits; reset/NRST/whole inhibit timing is not inferred from that calculation.

All enable/strobe/AO request GPIOs stay LOW. PA13/PA14 SWD, PF2 reset, physical slot straps and the parent sensor-I2C override on DIC PB3/PB4 remain reserved. DIC samples all24 real receiver GPIOs in the foreground, publishes an atomic snapshot and reports its real timer age. The diagnostic filter requires five disagreeing samples, nominal minimum10us apart; it is not the production configurable debounce contract. All five actual sensor/safety fault GPIOs must report healthy before the DIC health flag is set.

DO targets poll the actual two addressed TPS274C65 parts over SPI2 mode1. Every read deliberately writes a zero SW_STATE nibble, as required by the IC protocol. Address echo, SPI error, actual nonzero POR register0x21=0x0A, CRC_CONFIG=0 and full transactions are checked. The separate diagnostic cold-POR profile never changes output configuration or enables CRC. Driver CRC/configuration/commissioning for production remains engineering work. Read-to-clear fault observations are retained until reset; these are history latches, not claims that a former fault remains physically active. SW_STATE is a command register, not terminal-voltage measurement. Actual PB1 entry-good, PA2 latch, PA3 permission, PC6 enable and PB0 fault observations remain separate. Missing/stale reads never become zero-age valid data.

With this image, OUT_PERMIT remains LOW. The actual ACC_CLR_N chain consequently holds ADS8684A and both AD5683R DACs in reset. Their registers/conversions cannot be read in that state. ACC reports AI ageFFFF, validity0, DAC-readback validityLOW and actual clamp-control/rail GPIO observations. The separate diagnostic FPGA branch accepts a healthy held-reset/clamped control state without claiming fresh ADC data or terminal voltage. Live AI/DAC/ADS1115 acquisition, ranges/reference checks and commercial startup/authority sequencing remain engineering work. The historical synthetic0F test response has not been reused as physical evidence.

The separate FPGA candidate adds20us CS setup and5us final-clock hold at50MHz;320 clocks take38.4us, so the guarded transaction occupies about63.4us within the100us period. A reply prepared before a fault may complete once; subsequent bad polls withhold progress, three consecutive failures after initial qualification latch the lane, and recovery needs a new session. Missing/unready nodes at startup remain unqualified with all authorityLOW. A complete validated four-lane cycle produces one idle-LOW,1us-HIGH O watchdog pulse. Motion progress remains the independent historical six-axis/two-encoder diagnostic path; twelve fitted motor interfaces are not twelve proven coordinated axes.

Evidence is intentionally separate: four real ARM ELF/binary compilations; host execution of the same protocol C with5,389 negative/positive checks and sanitizers; HDL/C VPI tests using explicit GPIO fixtures; HDL lint/elaboration and synthesis. The VPI test executes the real shared protocol function, not the target DMA/ISR instructions or sensor hardware. No target has been flashed. GPIO/isolator SPI timing, timer synchronizer settling, ISR/reply deadline, current/thermal behavior, option-byte programming and loaded real-time operation require physical qualification. The35.8us idle gap before the next CS is not a guaranteed ISR worst-case bound from compilation.

ST and ARM Apache2 licenses are retained with unmodified pinned headers. GPL Icarus headers and the VPI shared object are internal simulator-only tooling, excluded from target ELF/bin; their distribution boundary needs review before shipping any test tooling. No original commercial software is promised as freeware or an open-source release.
