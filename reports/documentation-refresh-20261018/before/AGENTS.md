# Project context

Read `PROJECT_MEMORY.md`, `docs/BUILD_PLAN.md`, `docs/PLATFORM_ROADMAP.md` and the latest engineering status before changing this controller project. They record the user's decisions and proposals, including PCBWay turnkey manufacture, included touchscreen pricing, optional AI, CLI-first customization, replaceable modules and third-party accessories. The latest user decision (30 September 2026) is one active custom motherboard with a soldered FPGA and all twelve motor interfaces fitted, preserving at least eight usable motors and individual enable/alarm on all twelve, four ABZ encoders, 24 general DI and 16 smart general DO plus the remaining required interfaces. Commodity compute, ESP and storage/settings modules remain replaceable. This explicitly supersedes the passive fixed-base/thirteen-custom-card rack, removable FPGA/I/O cards and custom motors-9–12 expansion card; do not recreate that architecture. Read docs/MOTHERBOARD_IS2.md for the versioned physical transition, preserve the untouched external IS-1 archive and retained logical/electrical/fault contracts, and do not fake card-presence signals for integrated motherboard regions. Keep existing six-joint/two-encoder results labelled as historical baseline evidence, distinct from eight- and twelve-channel work and roadmap capabilities distinct from implemented evidence. The existing 327-part MC r0.4/revision-14 is partial source/native evidence to reuse, not a finished motherboard.

Keep the public CLI, configuration schema and UI on the same service contract. Use structured output, validation, preview/diff and reversible configuration changes; preserve actual electrical and motion limits. Preserve user source files and existing machine configurations. Development checks should use explicit simulation profiles and disconnected interfaces.

The display range covers 7-, 10-, 12-, 14-, 18- and 21-inch classes and further qualified sizes; read docs/DISPLAY_TIERS.md for current scope. Older 21.5-inch studies are individual cost scenarios, not a fixed product requirement. Keep screen size independent of machine I/O capability and cost each complete package.

Record the difference between source inspection, host tests, target compilation, HDL simulation, FPGA synthesis, circuit ERC, board DRC and physical measurements. Do not generate placeholder fabrication files or label an incomplete design ready for manufacture.

Power-off service uses approved commodity-module exchange or a whole-motherboard replacement through keyed pluggable terminal/harness groups. Whole-board replacement has different verification and cost requirements from the superseded card-swap target; do not promise a five-minute swap or reuse old virtual-card tests as physical proof. Preserve machine settings, the protected recovery/mirror/export contract, offline entitlements and deliberate inhibited restart. Screen size and licensing must not silently remove fitted motor channels or required I/O.
