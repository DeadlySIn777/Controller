# One supported machine, one complete experience

**4 October deep upgrade:** [implemented host/browser evidence](../reports/deep-upgrade-20261004/README.md) now includes 72-fact local intake into one twelve-motor definition, an exact-bound readiness and configuration/backup self-check, working native exports and reviewed browser backup recovery. This advances definition, configuration verification and recovery rows below. It does not close physical commissioning, live fault acquisition, qualified replacement or job/geometry acceptance. Fresh diagnostic firmware host checks/ARM compilation remain distinct from target execution and the older HDL replay sources.

4 October 2026. User priority: make the prototype intelligent about its own configuration and evidence before adding more features. Advanced internals should reduce the owner's work. The flagship target is one supported machine configured without manual HAL editing, physically commissioned, fixture located, job previewed, known fault correctly diagnosed, and a qualified replacement recovered through retained keyed harnesses and deliberate inhibited restart.

This is an acceptance path, not a claim that the physical controller has completed it. Claude continues the hardware routing. One soldered-FPGA motherboard with all twelve fitted motor interfaces remains the architecture. Removable compute, ESP and settings/storage units are commodity modules; integrated regions are not removable FPGA/I/O cards. Screen size and licensing do not remove fitted I/O.

Every consequential screen should explain what is known, what is missing and the next useful verification. Developer details stay in expandable source/limits views. An alarm code is not a wiring diagnosis; a commanded output is not a measured load. Actual qualified observations can support specific comparisons. AI reads validated definitions, observations, deterministic findings and approved documentation; it does not invent equipment, bypass validation or control motion directly. Offline routines finish without a provider; paid extraction remains deliberate, bounded, reusable and review-only.

The source instrumentation and identity provisions remain engineering gates. Hardware timestamps, current/voltage paths, independent inhibit supervision and commodity identity must be audited against exact source and real acquisition. This software pass does not alter Claude's PCB or certify those paths. The TPS274C65 family documents current/fault diagnostics, but circuit selection alone cannot identify a failed mechanical load or raise the current rating. [Texas Instruments](https://www.ti.com/product/TPS274C65).

The comparison target is supported industrial workflows, not universal STEP/DIR autotuning. Beckhoff describes drive-integrated mechanics/controller/filter identification; that needs compatible drives and measurement paths. [Beckhoff TE5960](https://www.beckhoff.com/en-us/products/automation/twincat/texxxx-twincat-3-engineering/te5960.html). HEIDENHAIN's fixture collision and reference-run monitoring features show why geometry, probing and repeatable evidence matter. [HEIDENHAIN TNC7](https://www.heidenhain.com/products/cnc-controls-and-digital-readouts/cnc-controls/tnc7). These are benchmarks, not implemented controller capabilities.

RAUC is a candidate for signed staged updates; slot layout, target integration, bootloader rollback and qualified health checks are still required. Our unsigned support/config/job archives are not RAUC bundles. [RAUC basics](https://rauc.readthedocs.io/en/latest/basic.html). Smooth 60 Hz interaction and under 100 ms ordinary local-touch feedback are development targets to measure under simultaneous controller load, not current timing claims.

Do not advertise impossible-to-lose settings, five-minute motherboard exchange, thirty-day fault retention, universal automatic identity/tuning, verified collision protection or physical readiness without their explicit evidence. The first release should close this one complete machine workflow before expanding the feature catalogue.
