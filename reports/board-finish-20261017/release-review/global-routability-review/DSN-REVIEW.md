# Independent global-router setup review

The original `prepare_global_DSN_constraints_r1.py` outputs should not be used for a long routing run with their raw keepouts unchanged. The domain assignment and clearance matrix are sound; the hard-area translation is not.

**Fix before routing:** the first raw structure keepout is the entire U1001 F.Cu special-neck rule area, x153.290–169.290/y81.677–97.677 mm. Its actual native track/via flags both allow routing. The exporter also hardens the U11012 neck region, two converter pour-only exclusions and five local fill-clearance trial areas. These are 19 falsely hardened per-layer board scopes, apart from the five separately conditional TMR areas. Blocking the FPGA escape this way would make a global result misleading.

The independent helper is `release-review/native_DSN_keepout_manifest.py` (`build_manifest()`). Its owner-aware output is [native-DSN-keepout-manifest-r2.json](native-DSN-keepout-manifest-r2.json). It provides **534 board-owned native hard scopes**, plus two footprint-owned scopes already represented correctly in the library. Preserve the existing **74 library keepout scopes**, including mechanical hole obstacles and the J1002 via-only restriction. Do not delete those along with the erroneous board scopes. The manifest retains literal per-layer polygon/hole geometry and supplies the five DRU TMR conditions separately.

**TMR restrictions require an explicit conservative-donor label.** Their native DRU excludes unrelated copper while exempting their own footprints and listed own nets. Plain DSN keepouts cannot encode those net exceptions. An all-net donor restriction blocks legitimate own-pad routing: each actual TMR triangle intersects own pads 1, 2 and 3. Do not attribute resulting failures to placement or relax native rules on import. Also, all five native TMR outlines are triangles rather than the full rectangular courtyard envelopes described in the DRU comments. For U14601 the saved native polygon literally has only `(381.1,104.575)`, `(356.9,104.575)`, `(356.9,92.875)`. Preserve the actual shape during translation; correcting the intended physical under-converter envelope is a separate source-design change.

**A 1 nm DSN declaration does not preserve 1 nm geometry here.** Freerouting limits geometry using `CRIT_INT=33,554,432` and reduces the import scale by factors of ten while five times the maximum coordinate exceeds that limit. A 450,000 µm board requesting resolution 1000 therefore scales 1000 → 100 → 10, retaining the same **0.1 µm internal grid** as resolution 10. A higher declaration alone cannot solve collapsed tiny fill features. Any actual-fill variant needs conservative geometry/topology checks on that effective lattice and a clean parser result before routing. [Primary scaling implementation](https://github.com/freerouting/freerouting/blob/v2.4.1/src/main/java/app/freerouting/io/specctra/parser/Structure.java#L1136), [numerical limit](https://github.com/freerouting/freerouting/blob/v2.4.1/src/main/java/app/freerouting/geometry/planar/Limits.java#L7).

The following independent checks pass on the prepared r1 files:

- All **2,388 exported nets** have exactly the expected domain class when checked against both the current `.kicad_pro` literal assignment/pattern entries and the normalized actual-model domain map. All active nets are in the 24 domain classes. The 12 NC_ISOLATE patterns refer to absent historical J195xx nets; they are not an omitted active class.
- The output contains all **595** expected pairs among 24 domain classes and 11 fill aliases. Every different-domain pair has 0.6 mm clearance, with no missing or wrong cross-domain pair.
- All **10,188 polygon-wire fills** name one of the 11 declared clearance aliases. This is supported semantics: `Network.addClearanceRule` creates a clearance-matrix class with the netclass name, and `Wiring.readWireScope` resolves an explicit `clearance_class` before inserting a conduction area. These functions were inspected in the locally archived v2.4.1 primary sources. [Network implementation](https://github.com/freerouting/freerouting/blob/v2.4.1/src/main/java/app/freerouting/io/specctra/parser/Network.java), [Wiring implementation](https://github.com/freerouting/freerouting/blob/v2.4.1/src/main/java/app/freerouting/io/specctra/parser/Wiring.java).
- Native netclasses restrict new vias through `circuit(use_via "Via[0-5]_600:300_um")`. The four structure via-padstack definitions are required to represent existing sizes; their presence does not itself authorize four new-via sizes.

**Router connectivity is still an interchange result.** Of 8,012 retained old vias, 1,387 have partial actual native copper masks: 618 on two layers, 475 on three, 293 on four and one on five. Raw DSN represents all old vias using six-shape diameter-based padstacks. This can introduce annuli/plane contacts absent from the native board. A zero-unrouted DSN result therefore cannot establish native closure. Exact native via masks, real finite-contact groups and source/return/current checks remain required after import, alongside the separately acknowledged power-width and safety limitations.
