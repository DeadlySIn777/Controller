## Corrections found during engineering

- LinuxCNC run completion cannot be treated as a quick synchronous command acknowledgment. The adapter dispatches appropriate motion commands asynchronously and observes their actual completion.
- Request deadlines are checked again after status reads and before each individual command write; a slow mode change cannot make a stale motion request execute later.
- A first ESP counter sample does not prove progress. The helper now requires a later forward change within the same observed boot. Diagnostics remain advisory because UART queue age and sender authentication are not established.
- The previous field-side small-LDO allowance could dissipate 1.25 W at the proposed maximum input. That branch needs a switching regulator. The ESP also gets a separate regulated branch. The older cost comparison is explicitly annotated with these corrections and remaining unknowns.
- The electrical study's 250 ksteps/s goal is not achieved by the current reference RTL. Its tested configured cap is 195,312.5 steps/s at an assumed 50 MHz clock. Raising that cap alone cannot reach the goal: with the 100/100-tick STEP high/low defaults the minimum fault-free STEP period is 201 core ticks, a ceiling of 248,756 steps/s, and the RTL testbench shows that a 250 ksteps/s rate increment latches a timing fault ([gateware validation](GATEWARE_VALIDATION.md)). Physical rate capability remains unqualified.
- Power budgets currently warn about less than 20% headroom on two proposed rails. Numerical reservations and regulator capacity still need optimization and measurements.
- Integration review added host-age and implausible-counter checks, coherent encoder/index wrap handling and configuration freezing. The new controlled exception permits step-scale changes through a stopped acquire/commit/release transaction, with active HAL scale pins read-only and actual joints unhomed. Encoder scale and channel mask retain mutation-fault behavior. The compiled reference still uses a simple digital pulse-count correction loop, not a qualified physical servo design.

## What prevents board release

The [repair and memory specification](../docs/MODULAR_REPAIR_AND_MEMORY.md) requires retained wiring, grouped replaceable sections and a complete machine-configuration cartridge, separate from firmware and module factory calibration. The fixed wiring base, removable FPGA/custom cards and pending one-PCB discussion are superseded by the adopted IS-2 active motherboard. Approved commodity modules remain replaceable; soldered regions require whole-motherboard service through retained keyed harness groups, with separate physical verification and service-time evidence. The [disconnected recovery demo](MODULE_REPLACEMENT_DEMO.md) preserves settings across a virtual input-bank exchange, uses its own fixture calibration metadata, recovers valid records after simulated torn/corrupt writes and imports into a new store without weakening ordinary backup identity checks. All paths remain inhibited/unhomed with no run permission. Its two example records occupy 13,812 bytes. Physical memory, connectors, bus/power protection, preprogrammed replacement logistics and their added manufactured costs remain unresolved. The [original note](../research/user-notes/2026-09-28-repairability-memory.txt) is preserved unchanged. Existing backup files alone do not satisfy physical interrupted-write qualification.

The original ledger validator records **54 open design/release items** and zero consistency errors; that historical count is not a fresh count of all findings in the connected circuit review. The remaining categories are:

1. Complete power/protection, permission and I/O schematics; exact fitted support parts; package/bank/pin assignments and machine-interface compatibility.
2. Vendor device implementation, package/resource fit, timing closure, board wrapper and the board coupling of the useful-progress watchdog signal. The RTL now has a `progress_wdi` output that toggles once per accepted sequence-valid UPDATE; its connection to an external watchdog on a board remains open. Actual Yosys Efinix-family synthesis now passes; it does not prove T20 placement, timing or a working bitstream. The current endpoint omits the full field-I/O/analog/probe feature set.
3. A qualified physical Pi/Rockchip CNC1 SPI backend and target Linux/graphics configuration. The ROCK 3C host named in the six-joint ledger is an earlier engineering baseline; the compute choice remains open within the [CM4/CM5-style carrier study](../docs/COMPUTE_CARRIER_STRATEGY.md). The new Linux spidev implementation is a compiled laboratory backend with mocked syscall checks; its synchronous ioctl has no enforced deadline. The actual-runtime HAL still uses RTL simulation. Neither result establishes physical timing or machine-ready motion behavior. Python stays outside the cyclic path; unmodified Mesa drivers do not implement CNC1. The release manifest's `link_prototype_measurement` item requires the bounded pre-layout physical link measurement on an engineering host and FPGA evaluation board; acquiring them is a user purchase decision.
4. PCB layout, fabrication outputs, placement file, full ERC/DRC, mechanical/display integration and reviewed assembly/test instructions. The [PCBWay submission checklist](../manufacturing/PCBWAY_SUBMISSION_CHECKLIST.md) lists every file and decision a turnkey order needs and their current state; the design is **not ready for PCBWay manufacture**.
5. A complete fitted-BOM/PCBWay quotation and viable total bundle economics. Public reference prices cannot stand in for turnkey procurement and finished-product cost.
6. Physical power/reset/fault/timing/thermal/EMC and machine tests after appropriate engineering prototypes exist. The current software results cannot replace these measurements.

The UI/CAD import experience, production network authentication, wireless recovery, ESP accessory automation and AI application remain unfinished. Durable XYZ-scale activation and restart reconciliation now work in actual LinuxCNC/RTL simulation. The complete machine-profile store/cartridge, production runtime authority and physical commissioning remain unfinished.
