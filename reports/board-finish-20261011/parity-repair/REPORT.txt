run_native_parity.py takes generic --board and --out arguments. On a new output
it first freezes the exact board/source inputs and performs the portable checks.
On an already prepared output it verifies all snapshot hashes and requested
board identity. Then, only when root schedules it, it takes the test-only KiCad
slot (or --slot shared/main when root schedules that existing slot) and invokes
the exact frozen tools/quality/netlist_parity.py with
--no-connectivity. It loads the board read-only, without a requested connectivity
rebuild, zone refill, DRC or board save. Tool exit, elapsed time, report hash and
all frozen hashes are recorded; no source adoption is performed. --with-project
creates an exact candidate/integration project/library clone and uses the
separate native_bound_entry.py adapter to call SettingsManager.LoadProject and
BOARD.SetProject. The unchanged parity tool then runs against that binding; the
project is unloaded with saving disabled. The original tool is not patched.

mismatches. The wrapper therefore additionally requires parity_ok, integer zero
defect/category counts, no contradictory node assignments, exact board/export
hashes and exact inventory agreement with the portable precheck. It fails
closed on a missing report field or inconsistent schema. It records the API
check as source/native inspection and never equates it with CLI schematic DRC
parity. The host controls use a historical native report only as a synthetic
