# Current SIM2 runtime integration

The new `gateware/v3/runtime` source is an executable disconnected simulation candidate. It joins real streamed CNC3 96/176-byte SPI, CAP3 discovery, motion and I/O commissioning, twelve generators, four ABZ counters, 24 DI, sixteen applied-output readbacks, two probe captures, four index captures and a 256-entry event ring. The original archive and previous candidates remain unchanged. This candidate is not adopted for production and its physical-authority and production-completion outputs remain constant false.

`receipt.json` binds current source hashes, preservation checks and immutable execution receipts. `integration-r13` passes 1,190 wire assertions including every individual alarm input. These assertion counts contain repeated commissioning, response CRC and output-inhibition checks; they are not 1,190 independent qualification cases. Event-storage checks pass 11 assertions, including the earlier nine capacity/acknowledgment assertions. Provider boundary checks pass seven assertions, and the default-deny top remains inhibited over 10,000 model cycles. The three `mutation-*-r03` copied-source controls detect identity bypass, incorrect event acknowledgment and a missing applied DO bit at their intended assertions. They tested the same frozen RTL with the earlier 722-assertion fixture; the later addition only adds the twelve alarm-input cases.

The direct RTL fixture uses authored model inputs and timed watchdog drops. It verifies actual serial frames and actual compiled RTL but does not establish the continuous C host/provider/LinuxCNC integration result. That result is recorded separately under `../host`. No physical circuit or target was accessed. Home inputs are observations, not automatic homing permission. Physical IOL1 identity, acquisition and MCU output application, analog/PWM/process/frequency/MPG/expansion functions, telemetry mirror and additional diagnostic pages remain outside this profile.

The event implementation preserves seven simultaneous producers and depth 256 using eight single-write RAM banks. Pending-write and prefetch guards prevent stale RAM after SYNC from appearing as a new event. Only the exact current event actually delivered by a complete CMD transaction can be acknowledged. The source adds a separate output-domain gate/OPI handshake; it preserves the historical four motor domains and requires fresh neutral applied-output feedback before rearm.

`unified-family-r04` completed generic Yosys `synth_efinix` mapping of the functional `cnc3_runtime_sim` top with zero structural check problems: 34,493 LUT4, 7,776 ADD, 9,900 FF, 64 RAM5K and one clock buffer. This is a resource-closure blocker, not vendor device fit or timing evidence. The default-deny top was not substituted to obtain a trivial small mapping. Earlier monolithic and first banked mappings timed out and are preserved. Further resource experiments must use report-local copies while this source remains frozen for integration.

All first failures remain available. In particular, `integration-r02` exposed a test that drained events longer than the real 5 ms watchdog without updates; the fixture now sends legal progress while draining. `integration-r12` used timing-status byte26 for alarm feedback; `integration-r13` corrects the test to alarm byte28 and latched-alarm byte30. Neither correction relaxes RTL behavior or frozen deadlines.
