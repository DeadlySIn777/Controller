# Recorder, machine-state and archive audit

4 October 2026. Implemented source corrections in `controller_config/diagnostic_recorder.py`, `machine_state.py`, `diagnostic_explanations.py` and `package_archive.py`. Verification uses disconnected simulation records, temporary files and actual host Zstd. No API calls, motion commands, device connections, routing edits or electrical/motion limit changes were made by this audit.

## Corrected defects

| Finding | Resulting behavior and adversarial verification |
| --- | --- |
| A replayed lower source sequence with a newer timestamp could refresh machine state. | Sequence/timestamp contradictions quarantine the supplied producer stream. Input order does not establish authority. |
| Conflicting newest identities, or a malformed newest current-bound sample, could expose an older valid-looking fact. | Older facts from the inconsistent producer become unavailable. Independent valid producers remain usable. Old configuration bindings are rejected without tainting newer valid bindings. |
| Only identical timestamps triggered conflicts between producers; age metadata could create false conflicts. | Contradictory fresh producers are unavailable at different timestamps too. Agreement is assessed on the typed value and unit. Expired disagreements do not override current facts. |
| Multiple valid sequence updates at one timestamp were mistaken for conflicts. | The newest sequence from each producer is selected before comparing independent producers. |
| The first record's failed manifest commit could strand a chunk without a store identity. | An empty identity is committed before the first chunk. First-record retries recover without inventing accepted history. A fully validated empty initialization transaction interrupted before replacement can be adopted only during an explicit append retry. |
| Process death before replacing a manifest left an unrecognized temporary file. | Recorder transaction names carry the store identity. Read-only operations report pending owned transactions and preserve them; an explicit writer reclaims them. A real terminated subprocess verifies the recovery path. Partial initial metadata and foreign identities remain preserved and fail closed. |
| File reads trusted a pre-read size check and followed manifest/lock links. | Bounded regular-file descriptor reads check identity and size while opening/reading. Lock files must be bounded regular files, and unreadable, oversized or replaced evidence is preserved. |
| An empty lock could be initialized before acquiring ownership or through a hard link to a user file. | Native ownership precedes initialization; held empty locks stay untouched and return busy. Recorder locks require one filesystem link. Actual hard-link and native-lock regressions preserve the source bytes. |
| An OS unlock/close exception could permanently retain the process-wide mutex. | Mutex release runs unconditionally, OS lock errors become structured recorder errors, and later operations still work. |
| Sealed source acknowledgments were not checked against retained last-record bytes. | The accepted flag, timestamp and canonical record hash must match retained last-record evidence. A seal remains corruption detection, not authentication. |
| A gap ending at the fault contaminated the post window; a gap starting at it contaminated the pre window. | Pre/post coverage uses the affected side of the boundary. Zero-duration requested windows require no external history. Gaps and missing history remain explicit. |
| Deep record nesting could exhaust `deepcopy` before validation. | Bounded validation runs first, oversized observation text is rejected before serialization, and excessive nesting produces a structured error without creating storage. |
| Boolean response observations accepted numeric units. | Incompatible units cannot confirm inhibit, enable or alarm signals. Actual rest, position retention and restart remain unverified. |
| Archive publication did not sync the POSIX directory, and lost link acknowledgments were indistinguishable from a failed publication. | The directory is synced on POSIX. A complete published artifact is preserved and returns `ARCHIVE_PUBLICATION_UNCERTAIN` when durable publication was not acknowledged. Retry cannot overwrite it. Outer receipts explicitly separate integrity from sender authentication. |

## Evidence and limits

[Focused verification](storage-verification.json) and [case log](storage-verification.log) record exact source hashes, counts and skipped cases. The new cases exercise contradictory producers, same-time sequence updates, source regressions, malformed bound records, first-write failures, lost acknowledgments, actual child-process death, quota/gap behavior and archive publication races. Existing normal, original example and version-two example recording directories are read and hashed before/after to verify source compatibility and preservation.

These are source inspection and host tests. Windows file flushing and atomic host replacement/exclusive links are not a physical power-loss qualification. An initial transaction torn before it contains a fully valid empty manifest is preserved for deliberate inspection rather than guessed. Existing recorder manifests and observations are not rewritten by status/report. Compression, validation and disk writes remain synchronous non-real-time work; partial-chunk rewrites still require production batching/queue, CPU/load and media endurance measurement before a flash-wear or target-timing claim. Single-frame/checksummed Zstd, 8 MiB window, strict inert USTAR files, bounded inventory and payload, quota, and no dictionary/extraction/execution behavior remain unchanged. Configuration-bound simulation readings do not authenticate hardware, qualify installed presence, prove a stop, restore homing or authorize restart.
