## Connection behavior relevant to offline work

- Page initialization constructs the whole app on DOM ready: [app.js:2202](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:2202>).
- If saved connection type is WebSocket and a saved IP exists, init schedules a connection after 500 ms: [app.js:81](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:81>). `loadSettings()` restores the IP field before that call: [app.js:1933](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:1933>).
- The adapter creates a real WebSocket: [grblhal.js:285](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/grblhal.js:285>). On open it starts heartbeat and sends `?`, `$I`, `$G`: [grblhal.js:330](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/grblhal.js:330>). App connection handling additionally queries `$$`: [app.js:263](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:263>).
- Unexpected WebSocket closure can schedule reconnection: [grblhal.js:354](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/grblhal.js:354>), [grblhal.js:380](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/grblhal.js:380>). USB requests a user-selected port and then opens it: [grblhal.js:201](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/grblhal.js:201>).
- No automatic motion-on-page-load was established. Automatic connection and queries are enough to make launching the unchanged page unsuitable for this read-only task. An offline scene editor should inject a disconnected adapter before app initialization, rather than relying on not pressing Start.

## Integration gaps to account for

1. Renderer selection is not wired to the available WebGL class. `app.visualizer3D` is referenced by shortcuts at [app.js:1595](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:1595>) but is not constructed. The 3D constructor takes a container, while the active constructor takes a canvas.
2. Simulation callback signatures do not agree: [app.js:726](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:726>) expects `(pct, pos)` and calls `setSimulatedPosition(pos)`, but [gcode-simulator.js:296](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/gcode-simulator.js:296>) emits one object. Neither reviewed renderer defines `setSimulatedPosition`; both provide `setToolPosition(x,y,z)`. This is a static finding, not a reproduced runtime result.
3. Workspace settings update the visualizer and AI only: [app.js:1956](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:1956>). Simulator defaults are independently `400×400×100`: [gcode-simulator.js:18](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/gcode-simulator.js:18>), while app defaults are `400×400×200`. Its `setGrbl()` can copy machine limits, but no call was found in app.js. One machine profile should feed these consumers.
4. [app.js:1814](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/app.js:1814>) starts controller streaming directly after checking loaded lines and idle state; it does not require `simulateGCode()` first. Imported setup geometry must not silently alter or authorize this path.
5. Three.js geometry uses CNC-to-renderer axis conversion `(x,z,y)`: [visualizer-3d.js:443](<Z:/Programming Projects/Genmitsu1030Cnc/fluidcnc/visualizer-3d.js:443>). New models need an explicit units/orientation/placement conversion shared with toolpath and status rendering.

## Minimum additions while preserving the UI

1. **Confirm the candidate** before adapting source. Preserve page layout, control names, colors, toolbar behavior, and existing workflows once the exact reference is identified.
2. **Inject a controller interface** at `setupGrbl()`: existing adapter for deliberate live use; inert offline adapter for scene setup and trace playback. Keep connection creation/reconnection outside rendering/import code. No machine command methods in scene objects.
3. **Add one scene data model** containing machine profile, coordinate frames, stock, fixture instances, tool/holder geometry, and external asset references. Store millimeters and transforms explicitly; keep scene persistence separate from live controller settings.
4. **Normalize a renderer interface** around existing `setToolpath`, `setToolPosition`, `setView`, resize, and envelope updates. Make Canvas2D and Three.js selectable behind the existing viewport; do not replace the entire app to gain model loading.
5. **Add setup editing within the current visualization tab**: import model, choose units/orientation, set placement, toggle visibility, save/load setup. Use dedicated mesh loaders for fixtures/machine geometry; retain SVG/DXF import for its existing 2D-path role.
6. **Consume an immutable simulation trace** from the actual upstream controller engine for playback. Keep browser preview/estimate explicitly distinguishable from actual planner traces and from future collision checking.
7. **Add offline contract checks** for no transport calls during setup, coordinate/units transforms, persistence round trips, imported geometry bounds, renderer method compatibility, and trace-position agreement. Runtime visual review remains outstanding because the app was not launched.
