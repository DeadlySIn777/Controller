# Archive note: ESP evidence before the 2026-09-28 audit fixes

This directory preserves the ESP32-S3 evidence identity that was current before the audit fix pass of 28 September 2026: the prior `SHA256SUMS`, `default-build.log`, `uart-build-check.log`, and byte-identical copies of the then-current `reports/ESP_SERVICE_BUILD.json` and `reports/ESP_SERVICE_BUILD.md`. The two prior images, `cnc_service-esp32s3.bin` (177,376 bytes, `a43b3f4e...`) and `cnc_service-uart-compile-check.bin` (202,352 bytes, `42b53c37...`), are kept here byte-exact. They were overwritten in `../` by the audit rebuild and were restored into this folder from the pre-fix snapshot of the tree; `sha256sum -c SHA256SUMS` in this folder verifies all four files. They have to be kept because the build is not reproducible (`CONFIG_APP_COMPILE_TIME_DATE=y`, `CONFIG_APP_REPRODUCIBLE_BUILD` unset), so a rebuild cannot recreate them. There was no prior `manifest.json`; the prior evidence identity was `SHA256SUMS` plus the report JSON. The archived JSON's `source_sha256` for `main/service_main.c` and `main/Kconfig.projbuild` did not match the source present when this archive was made (both files were modified at 04:27-04:28 local time, after the archived logs were produced at 01:05; the current files contain the compile-time RX GPIO guard and expanded help text), so the archived images and logs should be read as predating those source changes. The audit then named the 1000 ms / 500 ms freshness deadlines, documented the host cadence, strengthened the corruption test and added `record_evidence.py`; both variants were rebuilt with `build-local.ps1` and the host core tests rerun, and the current evidence is `../manifest.json` and `../SHA256SUMS`. Nothing here is a release or flash image, and no device was flashed.
