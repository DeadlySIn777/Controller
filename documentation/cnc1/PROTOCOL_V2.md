# CNC1 ABI v2 discovery extension

The actual `gateware/rtl/cnc_endpoint.v` implements this opt-in extension with `ENABLE_DISCOVERY=1`. Default `0` retains ABI v1. Its regression (252 counted checks) and a separate ABI v2 capability testbench (27 checks) are recorded in [gateware validation](../reports/GATEWARE_VALIDATION.md); the same `gateware/tools/run_tests.sh` sequence was rerun for this package into `cnc1/evidence/baseline-regression.log` (HDL simulation and lint only). The older "180 checks" figure is historical (`cnc1/evidence/baseline-v1-before-extension/`). Neither ABI is Mesa HostMot2. The v2 driver accepts exactly the fitted six-step/two-encoder reference; it does not advertise the proposed eight/four design.

All existing [v1 framing, CRC, command fields, atomic commit, authority, pulse generation and watchdog rules](../gateware/PROTOCOL.md) remain, except byte 4 must be **2** in every v2 command and response. No automatic v1/v2 fallback is implemented. Unsupported versions fail closed. Ordinary status keeps magic `CNS1` and its previous layout, with version byte 2.

**Opcode 5: read capabilities.** Command bytes 6–61 must be zero. It is accepted only while disarmed. It does not arm, establish a session, clear faults or feed the watchdog. Its own simultaneous response still describes the prior snapshot. An accepted opcode 5 leaves the page pending. **The next completed transaction, whatever its opcode and whether the endpoint accepts or rejects it** (bad CRC, wrong length, early chip-select release), returns the capability page, because the response is snapshotted when chip select asserts, and consumes it. Ordinary `CNS1` status resumes with the transaction after that. A rejected frame also latches the endpoint frame fault, as for any rejected frame. A lost or corrupted page read therefore needs a new opcode 5; there is no second copy. The shipped driver always follows opcode 5 with a NOP and treats anything but a valid page as `CNC1_BAD_CAPS` (explicit stopped reset retries discovery). Asking for capabilities while armed is a protocol fault.

| Capability response bytes | Encoding/value |
|---|---|
| 0–3 | ASCII `CNC2` |
| 4 | ABI 2 |
| 5 / 6 / 7 | STEP channels 6 / ABZ encoders 2 / frequency channels 0 |
| 8–11 | Big-endian feature bitmap `0x0000001f` |
| 12–15 | Core clock parameter in Hz: 50,000,000 |
| 16–19 | Maximum signed rate magnitude: `0x01000000` |
| 20–21 / 22–23 | STEP high / minimum low ticks: 100 / 100 |
| 24–25 / 26–27 | DIR setup / hold ticks: 100 / 100 |
| 28–31 | Watchdog ticks: 250,000 |
| 32–61 | Reserved zero |
| 62–63 | CRC-16/CCITT-FALSE over bytes 0–61 |

Feature bits 0–4 mean STEP generation, AB quadrature, index latch, atomic multi-channel update and watchdog. No general I/O, frequency measurement, analog, probing, spindle actuator or physical-board identity is advertised. Descriptor values come from the actual compiled RTL parameters; they are not a physical measurement or permission to exceed drive/cable limits.

The C state machine distinguishes discovery, OFF, pending SYNC, READY, pending ARM, ACTIVE, pending DISARM and FAULT. SYNC requires an explicit reset edge with enable low. ARM requires a subsequent enable edge and zero rates; nonzero updates wait for its later acknowledgement. Returning communication or a held-high enable never clears FAULT. Discovery failure permits an explicit stopped retry; sequence exhaustion faults rather than wrapping. A reset creates a different session. This is an accidental-stale-command contract, not cryptographic replay protection across complete host/FPGA resets.

The common driver checks CRC/version/reserved fields, expected session/sequence, core-time advancement and host sample age. At discovery it converts the advertised watchdog to `watchdog_ns = watchdog_ticks * 10^9 / core_hz` (5 ms for 250,000 ticks at 50 MHz). Before any SYNC, ARM or UPDATE frame, `cnc1_write` refuses a servo period greater than `watchdog_ns / 2` with a latched `CNC1_CONFIG` fault; such a period leaves no margin for one late cycle, and a period at or above the watchdog would trip it between every pair of UPDATEs. The earlier fixed 10 ms period ceiling remains as an outer bound. Host sample age is limited to the smaller of the configured `max_age_ns` (5 ms default) and `watchdog_ns`. Only the Verilator HAL build sets the explicit `simulation_age_override` flag with a 500 ms wall-clock allowance (see below). These rules are source- and compiled-harness-checked with the actual RTL page and synthetic `CNC2` pages (250,000 and 20,000 ticks); they are not target timing qualification. It unwraps counters using modulo deltas within one driver session only: an explicit reset (SYNC) re-baselines the unwrapped step/encoder counts from the raw 32-bit RTL counters and discards accumulated wrap epochs, so position continuity across a reset is not a contract and retained positions must be rehomed or reverified; emitted-count changes must fit the advertised DDS limit plus quantization margin. Encoder plausibility uses the RTL logical ceiling of one transition per core tick, **not a qualified electrical input rate**. Index values use the nearest modulo epoch relative to the continuous count, valid only while the latch is less than 2^31 counts old. The sticky index flag is not a timestamped event queue.

Configuration scales and axis mask freeze with the first ordinary feedback sample. Later mutation faults before rescaling feedback or publishing another command. Startup configuration is permitted unconditionally. Changing step scales after the freeze is possible only through the bounded stopped transaction `cnc1_configure` (operation 1 acquire inhibit, 2 commit scales, 3 release, 4 stage the persistent-pending inhibit) and, in the durable profile, `cnc1_persistence_commit` (HAL `config-op` 5). The guard requires discovery, READY state, valid feedback, no enable/reset edge, endpoint disabled with zero mask, and matching session/revision/epoch. Only the six step scales can change; encoder scales and the axis mask still fault on mutation. The persistent acknowledgement additionally requires that `config_revision` advanced (a stopped operation-2 scale commit) after the gate was last staged by operation 4 or at HAL load; otherwise it returns result 5. So the sequence 4, 5, 3 without 2 is refused, and uncommitted startup or staged values cannot be acknowledged or released without an explicit stopped operation-2 commit after the stage. The driver does not check the committed values: any in-range scales, including the 200-step defaults, can be committed by operation 2 and then acknowledged with an arbitrary hash, because the hash is opaque to the driver. Equality between the committed scales and the durable record is enforced only by the persistent service, and that service is not an authentication boundary against a privileged HAL writer. Result codes are listed in `src/cnc1.h` and in the [runtime configuration report](../reports/RUNTIME_CONFIGURATION.md). The service layer also unhomes the actual LinuxCNC joints and maps only X/Y/Z. See [runtime configuration](../reports/RUNTIME_CONFIGURATION.md) and [persistent runtime](../reports/PERSISTENT_RUNTIME.md). Error cause remains latched until explicit reset, and `cnc1.feedback-valid` drops on faults. Other displayed positions/status may be retained last samples during an outage and must not be treated as current verified position.

## Replaceable transport boundary

`cnc1_transport.exchange(context, tx[64], rx[64])` is the common C boundary. It exchanges exactly one frame and returns success/failure. The HAL build links only the implementation that clocks the actual Verilated RTL; a separate laboratory Linux spidev implementation (`src/spidev_transport.c`) compiles against this boundary but is not linked into the HAL build and is not deadline-qualified. The compiled HAL read function obtains feedback before LinuxCNC motion calculations; the write function publishes rates afterward. Python is only the acceptance-test orchestrator.

The simulation clocks the 50 MHz RTL in 20 ns ticks and implements mode-0 SPI at core/8, with the specified CS guards. One simulated servo period is 1 ms. It advances the core even when the simulated link is removed, so watchdog failure is exercised. Its wall-clock freshness allowance is explicitly relaxed to 500 ms by setting `max_age_ns` and the `simulation_age_override` flag in `hal_cnc1.c`, because Verilated RTL runs slower than real time. Without that flag the common code clamps the age limit to the discovered watchdog (5 ms default). Simulation clock progress and host wall time are recorded separately.

No qualified Pi SPI, Rockchip SPI or direct peripheral transport exists; the spidev backend has only mocked-syscall evidence ([report](../reports/SPI_TRANSPORT_IMPLEMENTATION.md)). Physical transports need measured exclusive bus ownership, bounded calls, response age and loaded-cycle qualification before use. The current position-to-rate calculation is a functional one-cycle integer pulse-error controller, not a mature tuned physical step/servo implementation. It closes emitted pulse accounting, not a mechanical feedback loop.
