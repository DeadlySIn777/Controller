# Archive: CNC1 evidence from the first audit-fix rerun (superseded by the repair round)

This folder preserves `cnc1/evidence/manifest.json` as recorded at 2026-09-28T20:11:23Z by `cnc1/tools/record_evidence.py`. That record covers volatile run `3ed8e8db-743d-4917-83db-db5ea47bcb34` (26 LinuxCNC checks, 1,116 trace rows, 14.8190 s wall / 3.1791 s simulated), persistent run `bc27e94a-4630-4b5f-bf98-1c863ca849c3` (68 checks in nine launches), 219 compiled C/RTL assertions, the 252 + 27 gateware regression and 32/29 host tests. Every log and JSON file listed in its `evidence_sha256` is copied byte-for-byte under its original repository-relative path; `archive-inventory.json` confirms each copy matched its recorded hash before copying. An independent review found that comments in `cnc1/src/cnc1.h`, `cnc1/src/cnc1.c`, `cnc1/src/hal_cnc1.c` and the reports overstated the driver's persistence precondition. They claimed the driver could never acknowledge or arm on the 200-step defaults, but an explicit stopped operation-2 commit of those values followed by an arbitrary-hash acknowledgement is accepted. The comments were corrected, a compiled-harness case asserting that limit was added, and the command block was made reproducible with new owned helpers. The build, spidev tests, both LinuxCNC suites, the gateware regression and the host suites were therefore rerun and re-recorded. The module `cnc1/build/cnc1_sim.so` recorded by this manifest is not archived; only its hash is retained. These files are historical evidence, not the current result.
