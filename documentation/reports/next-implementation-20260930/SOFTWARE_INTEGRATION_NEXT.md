## Reuse the architecture; replace the missing interface layer

End-to-end simulation is achievable without replacing LinuxCNC, FPGA timing or the CNC3 core architecture. Reuse the tested STEP/encoder principles, compiled C core, replaceable transport abstraction, Verilator test infrastructure and LinuxCNC read → motion calculation → write scheduling. A parameter change alone cannot do it: the current `gateware/rtl/cnc_endpoint.v` parameters cover watchdog, rate, timing, discovery and clock only; six-channel arrays/masks/ports and its two encoders are fixed. `cnc_spi_frame.v` fixes a 512-bit/64-byte transaction. `sim_transport.cpp` fixes 64-byte buffers, one CS and 512 transmitted clocks. `hal_cnc1.c` fixes six scale/position pins, two encoders and an XYZ acceptance mask.

Build a separate IS-1 endpoint and adapters alongside that historical implementation. Keep historical six/two manifests and logs unchanged. The new interface is **CS_FB = 176 bytes, CS_CMD = 96 bytes, ABI 3**, twelve 32-bit rate words and twelve 24-bit STEP/encoder feedback slots, all multi-byte fields big-endian. It is neither Mesa HostMot2 nor main's older symmetric 128-byte draft. Channel labels are M0–M11; expansion motors 9–12 are M8–M11.

## Missing ports and frames to bind explicitly

The new RTL top must expose or correctly connect these hardware-facing families; exact names/balls come from IS-1 `spec/terminals.json` and Codex's reviewed allocation, not from widening the old top silently:

- Separate host `CS_FB_n`/`CS_CMD_n`, shared mode-0 SCLK/MOSI and mutually exclusive MISO/OE; 50 MHz clock, reset and independently effective inhibit/defaults.
- Twelve STEP, DIR and active-low EN_N outputs; twelve alarm inputs, timing-fault/enable-after-gating/alarm-level/trip masks and installed/required masks. Bank A M0–M7 and bank B M8–M11 have distinct power/permission/qualification terms.
- Four base ABZ inputs plus eight EX8 ABZ inputs and encoder status/validity/index control; raw expansion/module presence, qualified identity/power/status paths. Uninstalled inputs are invalid, never reported as working zeros.
- `FPGA_MOTION_REQUEST`, `FPGA_OUTPUT_REQUEST`, **progress_m/progress_o pulses**, WD_M/WD_O feedback, OPI/rearm and permission feedback. The old `progress_wdi` toggle is incompatible: IS-1 requires a 1 µs pulse per accepted ARM/UPDATE for WD_M, with WD_O fed by accepted full-I/O progress.
- Machine safety-chain/reset-arm/contactor/STO status; bank/output-path interruption and power-good. Core/field readings owned by the host service must not be invented as FPGA measurements.
- For the subsequent full-I/O slice: four point-to-point IOL1 links (DIC, DOA, DOB, ACC), each 40-byte CRC-32C frames at the specified cadence; process/frequency/probe/MPG/PWM/analog/status paths and card-local default/accept-watchdog behavior.

Response selection must reproduce CAP3 discovery's pending page behavior and **snapshot-before-commit**. A CNS3 response from the command currently being clocked cannot acknowledge that command; the following CNF3 must confirm accepted session/sequence/state. Reuse generated layouts/rules/vectors, not hand-maintained offsets or the old 64-byte packed bit slices.

## HAL and service gaps that would otherwise hide integration defects

1. CNC3 currently exposes only a global enable. IS-1 also requires `cnc1.N.enable` requests: all required requests must match at global enable's rise; dropping one while armed disarms the whole configured set. Implement the mismatch diagnostic and clean-stop behavior, then wire LinuxCNC per-joint amp enable/fault. Global permission is not twelve independent physical EN_N circuits.
2. Implement M0–M11 command/feedback/emitted count/scale, enable-commanded, alarm/latched alarm, timing fault and position continuity, plus installed/expansion/config/fault/validity pins. Use the authoritative registry for the subsequent encoder, general I/O, safety, process, timing and telemetry pins. Do not create absent-hardware measurements merely to satisfy pin count.
3. The installed LinuxCNC development headers declare **16 maximum joints and 9 coordinate axes** (`rootfs/usr/include/linuxcnc/emcmotcfg.h:25–31`). Twelve motor channels fit that joint ceiling; twelve axes are a different claim. Machine-specific gantry/extra-joint/indexer mappings and homing still require correct profiles. Host all-channel traces and an actual LinuxCNC profile are distinct checks.
4. Freeze an applied configuration or reject live scale/timing/mask changes until a stopped validated transaction. Add encoder delta/validity bounds, semantic/reserved-bit validation of returned frames and telemetry invalidation/age handling identified in the audit before exposing them through HAL or the service.
5. Driver profiles must hold zero motion for the declared enable-settle time (the DM542T V4 reference requires ENA to lead DIR by at least 200 ms), and ensure high/low/setup/hold satisfy that exact drive. Current model bring-up can move a few cycles after ARM; it does not prove that physical sequencing.
6. `position-fb` from emitted STEP counts remains commanded-output accounting. Keep encoder measurement validity distinct, and invalidate/unhome after an unclean output-path interruption. Saved scale/calibration must never restore homing, job authority or automatically re-arm.

## Compatibility hazards to close first

- **Self-test mismatch:** IS-1 ARM requires both watchdog tests passed. `cnc3/src/cnc3.c` never sends SELFTEST; `cnc3/model/cnc3_model.c` ARM currently omits that precondition, while SELFTEST immediately sets one shared boolean. Those host/model bring-up tests therefore do not establish IS-1 bring-up. Do not weaken actual RTL ARM to match the current model.
- **Protocol interpretation mismatch:** the branch README lists four choices awaiting specification reconciliation: SELFTEST's overlapping byte rule, inherited channel-1 CONFIGURE_IO rules, structural-versus-semantic CONFIGURE rejection and JSON authority over Markdown. Resolve through reviewed versioned errata/new revision; preserve frozen IS-1 and existing golden evidence rather than silently editing it.
- **Build/evidence collision:** the historical `cnc1/tools/build.sh` deletes/copies fixed `/work/cnc1` directories, overwrites module output and writes evidence. New v3 tooling must use distinct build/rootfs/module/output locations and a separate profile selection. Never glob or reuse stale six/two Verilator objects, and do not run legacy recorders while new code is being integrated.
- **Capability overstatement:** the current model's CAP3 feature bitmap is a test-double value; encoders, IOL1, process signals and self-test hardware are not modeled. In a partial RTL milestone expose only implemented/valid paths or deliberately refuse required unsupported features; never fabricate valid status to get ARM to succeed.
- **Clock/rate scope:** IS-1 remains at 195,312.5 steps/s per channel; it expressly does not meet the 2,000,000 steps/s expanded qualification goal. Simulation runtime/wire arithmetic is not physical 1 kHz/700 µs completion or a 72-hour loaded result. Efinity fit/timing is still separate from this Verilator milestone.
- **Hardware interface receipt:** Codex's reset/watchdog repair must bind the exact polarity, progress pulse and independent latch/default behavior expected by logic. Correcting one historical supervisor path does not automatically implement IS-1's two watchdogs, all card protections or output-interruption latches. Review that receipt before a controlled merge or physical target build.
