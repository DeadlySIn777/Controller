# Independent processor integration review

28 September 2026. Read-only inspection of the actual thirteen-sheet assembly, FPGA and ESP service source netlists, pin contracts, primary-source extracts, validators and evidence helpers. No broad test run, circuit edit, device access or physical measurement was performed for this review.

## Findings and corrections

1. `hardware_check_connected.py` returned a list from `source_files()` but then called `paths.update()` and `paths.add()` in `main()`. That would stop the new evidence run before copying its inputs. The root removed those duplicate calls; the correction was verified by source re-read. The required RTL files were already included by `source_files()`.
2. The FPGA owner corrected local-reset R21 from 4.7k to 1k to include both configuration-time internal pull-ups and leakage. The independently inspected standalone netlist contains 1k. The first assembly inspected still held the older value and needs the owner's final native regeneration; it is not accepted as final source identity.
3. The root identified a separate initialization gap: dedicated CRESET releases before configuration and cannot by itself establish a post-configuration reset pulse for the user RTL. The FPGA owner is adding a distinct delayed post-CDONE user-reset path to D5. The permission circuit continues to observe local configuration reset and CDONE directly, with endpoint-ready clearing its latch. The new user-reset circuit and updated RTL bench remain pending in this review until their final source is available.
4. Independent primary-source inspection found an additional JTAG handoff condition. T20 datasheet page74 Table115 footnote26 starts JTAG tUSER after **both CDONE high and ENTERUSER received**. A timer started only by CDONE can expire before a programmer eventually issues ENTERUSER. Page80's single-FPGA SPI formula is t(A-to-B)+12µs. Therefore a post-CDONE delay must not be represented as a guaranteed reset for arbitrary JTAG programming; a separate user-reset hold or a bounded and qualified programming handoff is needed. This was reported to both owners before the new circuit was frozen.

## Connections inspected

- `PROTECTIVE_STATUS_FPGA` joins digital-input U5.OUT2 (pin5), its 100k bias, the permission block's 10k bias/U4.C input, and FPGA G16. No field voltage is connected to these logic pins. The ISO1212 primary table specifies VOH at least VCC−0.4V at 3V/3mA. The two pull-downs plus stated input leakage draw less than 0.4mA; the powered output therefore clears the LVC gate's 2V VIH screening boundary. This must remain a fixed reserved active-high assignment. ISO1212 brownout behavior and independent machine stopping remain outside that conclusion.
- CDONE has its intended IO_3V3 pull-up, the FPGA open-drain pin and the permission Schmitt input, with no competing pull-down or push-pull output. Service connector loading and continuous-voltage/full-temperature Schmitt margins remain qualified limitations, not a new guarantee.
- Upstream `FPGA_CRESET_N` drives the FPGA reset AND input; only the resulting `FPGA_LOCAL_RESET_N` reaches local configuration reset and the permission circuit. The service contact acts on a separate AND input, not against the sequencer's push-pull output.
- `HW_WATCHDOG_OK_N` is the raw local-reset/CDONE/external-permit/watchdog result. Endpoint-ready clears the external arm latch downstream. The final `TX_PERMIT` does not feed endpoint inhibit, so this connection does not create an arm/heartbeat dependency loop. Six AM26C31 enables receive the final permission; FPGA E6 is a proposed observation input whose direction still requires vendor implementation.
- ESP reset uses the upstream qualifier and a separate local reset contact through the configured Schmitt AND. USB VBUS reaches its detector/protection only and has no board-power connection. USB data orientation, switch selection and independent CC pull-downs match the declared contract.
- Incoming host/recovery UART buffers are powered from ESP_3V3. The outgoing UART buffer is powered from the external adapter's separate 3.0–3.6V VREF. The existing zero-supply leakage specifications support the bounded topology; arbitrary partial-power ramps, external overvoltage and USB/UART signal integrity remain unproved.
- LOGIC_GND and FIELD_GND remain distinct. No new 5V connection was found on an FPGA or ESP logic pin in the inspected netlists. The known AM26C31 input-versus-unpowered-VCC gap is not resolved by these checks.

## Evidence scope

The assembly validator reconstructs the source-net union, checks exact component values/MPNs/footprints, rejects changed aliases and checks source identities. Its tests cover loss of the programming-reset connection, wrong reserved interlock assignment and all twelve physical STEP/DIR connections. They do not establish correct FPGA pin directions, vendor fit, analog timing or twelve-channel runtime support.

The inspected execution helpers cover the selected test modules and their imported local helpers. The connected snapshot initially omitted four ESP firmware files named by the ESP block's own hash manifest. The root is adding those files as preserved contract sources, without claiming a new firmware build. The encoder-power primary PDF is stored inside its hardware block and is already covered by that block's recursive copy; there is no missing primary-PDF dependency there. The root is adding its report to the report inventory. The new master snapshot, rather than incidental old per-block UI-preference hashes, is the intended authority for the final run.

No additional concrete wrong-net/shared-driver defect was found in the inspected powered-state connections. This is not full-controller approval. Final source identity, post-configuration user-reset review, enlarged power/transient budgets, partial-power behavior, PCB/DRC and physical qualification remain separate gates.
