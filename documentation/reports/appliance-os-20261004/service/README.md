# Local appliance preferences and Files service

`controller_appliance` supplies one structured Python/CLI contract for the appliance UI. It writes only the selected workspace's `appliance/preferences.json` and stable `preferences.lock`. Read-only status, package inventory and previews do not create a workspace, initialize machine configuration or create an AI ledger.

Text size, reduced interface motion and starting screen use a workspace/revision/integrity-bound preview, an exact confirmation and a canonical request UUID. The opaque normalized workspace identity also prevents a first-use plan from being applied to a different empty workspace, while equivalent path spellings retain their binding. Reset is explicitly **interface preferences only**. It preserves machine configuration, machine backups, calibration, offline entitlements, the AI allowance, diagnostics and jobs. The retained previous preferences can be reviewed and restored until a later preference edit supersedes that reset. Concurrent writers, stale/expired/altered plans and conflicting request UUIDs fail closed. Accepted retries return their stored receipt. A lost acknowledgement after atomic publication reports uncertainty; status and an identical UUID retry resolve the actual saved state. File flush and local atomic replacement are host behavior, with no physical power-loss claim.

Full machine factory reset is blocked: the complete protected storage, entitlement, calibration and signed image recovery contract is not qualified. Service view requires a deliberate confirmation and lasts only for this service instance. It is presentation state, **not authentication or permission**, and cannot start a terminal, connect a device or send a machine command. This package reports its own absence of authority; it does not measure an external controller's inhibit or liveness.

Files inspects only the explicitly designated flat `workspace/packages` directory. A package must be an unlinked, bounded regular `.tar.zst` file and pass the unchanged existing archive manifest/member/SHA validator as configuration or support data. No archive extraction, configuration apply or sender authentication occurs. Download requires the opaque filename-derived identifier and reviewed SHA, revalidates the archive and compares the exact downloaded bytes with the validation digest. Missing Zstd remains visibly unavailable. The bounds are 128 scanned entries, 32 package names, 16 MiB per package and 32 MiB total inventory; a scan/total limit cannot silently return a partial successful inventory. Paths, linked parents, symbolic/hard links, Windows reparse/network paths and FIFOs are rejected. Arbitrary directories, machine stores and allowance/credential files are not browsed. Approved-folder placement and hashes do not authenticate the archive author or qualify its machine contents.

Fresh `run-r04/receipt.json` binds 29 test methods to their source and both executable surfaces. Windows passes 25 with four symlink/FIFO platform skips and actual Zstd config/support package and exclusive CLI-download tests. Linux passes 24 with five Zstd-unavailable skips, including actual symlink/FIFO and swapped-FIFO guards, local lock contention, publication fault/retry and reset/undo preservation. These are 29 methods run twice, not 58 distinct tests. All 24 original `controller_config` sources, the 71 frozen motion runtime inputs and both original reviewed runtime fixture stores remain unchanged. Every test creates its own temporary fixtures; no installed module or hardware endpoint is accessed. Earlier receipts retain their original pre-correction source snapshots.

Fresh `http-r02/receipt.json` separately records 23 actual local HTTP checks against the frozen root integration snapshot: inherited Host/Origin/header token checks; read-only cookie limited to package download; exact reviewed plans and UUID retries; full-reset, stale, duplicate-field and arbitrary-path refusal; native download bytes; interface reset/undo; and preserved machine/private/archive fixture bytes. The earlier `http-r01` snapshot is retained. Root UI/browser and OS staging evidence is separate. A fresh HTTP receipt is required if those root integration sources change. The canonical `receipt.json` combines the current service and HTTP scopes without treating platform repetitions as distinct tests or claiming physical qualification.

The shipping subset is exactly `controller_appliance/__init__.py`, `__main__.py` and `service.py`, with standard-library imports and the unchanged `controller_config.package_archive` dependency. Report scripts, test fixtures, preferences, credentials, allowances and existing machine settings are excluded from the OS payload. Physical commissioning, target boot/touch performance, live acquisition, loaded real-time deadlines, signed release and manufacturing remain unqualified.
