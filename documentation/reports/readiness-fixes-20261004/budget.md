# Durable setup budget and optional AI proposal adapter

Implemented 4 October 2026. Owned changes: `controller_config/setup_budget.py`, `tests/test_setup_budget.py`, `controller_config/setup_ai.py`, and `tests/test_setup_ai.py`. No hardware, routing, CAD, gateware, firmware or existing machine configuration was modified. No paid API request, provider credential read from the real environment, or machine connection was made during development/tests.

## Budget behavior

`BudgetLedger(path)` accepts a directory or explicit `.json` file. Initialization is explicit: `create(session_id, cap_microdollars=15_000_000)`. A lower cap, including zero, is allowed; an existing session/cap cannot be reset or topped up. Currency is USD, with integer microdollars throughout. `schema()`/`discovery()` describe the bounded API and inputs.

`reserve(request_id, payload_sha256=..., provider=..., model=..., model_version=..., pricing=..., limits=...)` computes a conservative maximum charge from approved integer token prices and fixed tool charges. Token categories are disjoint uncached input, cached input and output; output must include billed reasoning. Each fractional microdollar component rounds up. A reservation is committed before its first receipt grants `dispatch_allowed=true`. The exact payload/model/price/limit binding is immutable. Repeated IDs return existing state with `dispatch_allowed=false`; they never authorize another call.

All writers/readers coordinate through an OS advisory lock. Windows byte locks and POSIX flock release on process death; the stable lock file is never deleted while another process can hold it. The existing service atomic writer supplies a same-directory replacement, file fsync, Linux directory fsync and Windows replacement retries. A failed/uncertain write authorizes no call; a repeated ID after a lost successful-write acknowledgment observes the original reservation without another dispatch.

`mark_unknown` retains the reservation across timeout/restart. `settle(...actual_microdollars, evidence_id, usage)` records a positive authoritative final charge; an exact repeated settlement is idempotent and conflicting settlements are rejected. `resolve_no_charge` requires explicit provider-confirmed no-charge or proven cancellation before dispatch, plus evidence. Timeout/cancellation alone is insufficient. An actual charge over its reservation is recorded even above the entire cap, and permanently blocks new reservations. Other outstanding liabilities remain present and can still be reconciled. `freeze(reason)` additionally blocks new calls after contradictory provider model/usage evidence, without discarding existing liabilities.

The ledger has a 100-request ceiling. Tests explicitly bound worst-case serialized rows, including escaped labels and final billing usage, below the shared 2 MB document ceiling; space for settlement cannot be consumed by new reservations. Earlier implementation testing caught a too-large 128-row limit and it was reduced before delivery.

The checksum detects corruption, not hostile local rewriting. Locks coordinate a single host/local filesystem, not concurrent independent computers synchronizing copies through OneDrive. Host fsync/atomic-write evidence is not a qualified guarantee for every storage device under power loss. A corrupt ledger fails closed and is never automatically recreated. Provider-side account controls and trusted billing integration remain separate.

## Optional OpenAI adapter

Public API: `AiSetupAdvisor(service, ledger, cache_dir, provider_config, transport=None).advise(facts, expected_revision=..., allow_paid=False)`. The service argument is the existing disconnected `SetupService`; the advisor only reads status, missing fields and schema and invokes deterministic draft validation. It never saves, commits, commissions or actuates.

The administrator must explicitly supply an approved model/snapshot, model-version label, official pricing source, timezone-aware expiry, exact USD rates and maximum input/output tokens. No production model or price is guessed or selected in source. The approved fixed fee for the token-count endpoint must also be present (including explicit zero). The operator must opt into the specific bounded paid request. Only that send path reads `OPENAI_API_KEY`; missing-key preflight does not consume or poison a request ID. Tests inject fake transport and an empty environment when exercising missing-key handling.

The adapter reserves worst-case costs first, obtains an exact input-token count for the same model/instructions/input/structured-output schema, and only then submits one Responses request with bounded output, `store:false` and no tools. There are zero automatic retries or model-repair loops. The native HTTP transport allows only the hardcoded official endpoints and refuses redirects so authorization cannot be forwarded to another host. Count-then-generation errors retain liability; even a key becoming unavailable after a charged count cannot release the entire reservation.

Model output is strictly parsed into currently missing mechanical fields only. Each finite numeric value needs an exact source-quote substring from the user facts and an explicitly matching numeric token in that quote. Duplicate paths, already-filled fields, electrical/timing/resource changes, invented quotes, commands/tools, malformed output, refusal and incomplete output are rejected. These checks provide traceability and bounds, not proof that a model understood ambiguous equipment or units correctly. Accepted candidates remain unverified user selections for review and the deterministic validator. No physical compatibility or commissioning is inferred.

The cache binds the stripped facts, actual store/epoch/revision/draft/schema, advisor version and complete approved provider configuration. An unchanged replay uses zero provider calls, even without fresh paid opt-in. State changes before, during or after the provider work refuse stale proposals. The reservation's request ID also prevents a second concurrent/uncertain call if the first result has not reached the cache. Rejected completed responses are cached to prevent paid self-repair loops.

Provider usage yields a separately labelled conservative USD **formula estimate**, not a final invoice. The provider response ID and estimate are retained in the cache. The ledger reservation stays held until authoritative billing reconciliation. Missing usage retains the hold; an unexpected model or usage beyond reserved token bounds freezes new calls. The interface reports provider requests and generation calls separately (two and one for a completed fresh request; zero and zero for a cache hit).

## Validation

- **26 budget tests pass:** exact arithmetic, fractional rounding, invalid/unknown prices, immutable cap/bindings, restart, timeout liability, no-charge disposition, duplicate settlement, over-cap recording, freeze persistence, corrupt/duplicate JSON, failed atomic replacement, lost durable acknowledgment, real process races, process-death lock release, and maximum settlement storage.
- **21 AI adapter tests pass:** actual setup service/ledger/cache with fake provider; reservation before both HTTP operations; same-payload counting; explicit opt-in; expiring configuration; input bounds; no retries; lost billing/timeout; concurrent-state invalidation; field/quote/value rejection; malformed/refused/incomplete/tool outputs; cached replay; excessive usage/model mismatch; redirect refusal; and missing-key before/after-count behavior. Oversized JSON integers and quoted Decimal exponents now produce cached structured rejection. Provider usage beyond reservation freezes future calls even when the usage is too large for the cost formula itself. Pricing approval is rechecked after counting; expiry prevents generation and retains count liability, while previously cached advice remains available without spending.
- **Local HTTP failure integration passes:** `budget-http-failure-check.py` uses the real HTTP application, setup service, advisor and ledger with a fake provider and temporary store. Under a 24,000 microdollar cap, the first provider timeout holds 12,000; an exact replay sends no new provider requests; a second distinct timeout holds the remaining 12,000; a third distinct request fails before provider dispatch. Context reload reports the full held balance, and the setup draft is unchanged. No external network or API key is used.
- Commands: `python -B -m unittest discover -s tests -p test_setup_budget.py -v` and `python -B -m unittest discover -s tests -p test_setup_ai.py -v`, with `PYTHONDONTWRITEBYTECODE=1` and all mutable state in temporary directories. This is host/service test evidence; no live model evaluation, invoice reconciliation, target compilation, HDL/vendor implementation or physical qualification is claimed.

The OpenAI Docs skill was used for the adapter. The implementation was checked against [token counting](https://developers.openai.com/api/docs/guides/token-counting), [input-token count fields](https://developers.openai.com/api/reference/python/resources/responses/subresources/input_tokens/methods/count), and [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Those sources establish the request/response features, not a tested live account/model or a current selected price. An administrator must approve exact provider pricing and a compatible API model before a live request.

This closes the missing local budget mechanism and supplies a testable optional review-only provider adapter. It does not yet establish a fully evaluated CNC setup expert, first-time-right physical setup, actual cost per successful setup, or completed G26 acceptance.
