# SIM2 runtime profile, version 1

This directory is an executable **disconnected simulation candidate**. It is not an adopted IS-2 production top. `cnc3_runtime_sim` always reports `physical_authority=0` and `production_profile_complete=0`. The exact frozen CNC3 96-byte command / 176-byte feedback CRC transport is retained. External frozen archives and previous incomplete candidates remain unchanged.

CAP3 identifies `spec_revision=0x53494d32` (SIM2), `gateware_build_id=0xd3494d32`, feature bitmap `0x00017fff`, 12 supported motion channels and 4 supported ABZ inputs. Installed counts become 12/4 only after the implemented model-provider boundary validates and alarm sampling becomes valid. Telemetry mirror, MPG, expansion, analog, PWM/process and physical qualification are not advertised. Event depth is 256. A host must explicitly select a disconnected transport and this SIM2 profile; physical drivers must refuse it.

The versioned local CONFIGURE validator accepts integrated class0 with twelve motors. It rejects the legacy class1 removable motor-expansion convention. Lengths, CRC, timing100..1023 ticks, maximum DDS rate0x01000000, 50MHz clock and5ms watchdog are unchanged. The motion configuration hash must equal `sim_expected_config_hash`.

The simulation provider context is independent of the motion session. Its nonzero session and configuration hash are immutable throughout one simulation run. SYNC does not reset provider sequence. After RTL reset, the first snapshot sequence is1; each accepted snapshot must be exactly previous+1 without wrap. Required ports are `sim_context`, `sim_expected_session/config_hash[31:0]`, `provider_strobe`, `provider_tag[31:0]=SIM2`, `provider_abi[7:0]=1`, `provider_session/config_hash/sequence[31:0]`, `provider_valid_mask[7:0]=0x1f`, and `provider_faults[31:0]=0`. The five validity bits mean DI, DO, probes, home/limits and encoders. Default maximum age is440us; CONFIGURE_IO can reduce it to250..440us. Invalid, stale, changed or replayed snapshots latch a provider error until RTL reset. Typical heartbeat is100us. Raw DI/DO/home/limits latch atomically on accepted snapshots. ABZ/probe pins are continuously synchronized by actual RTL.

Motion `gate_high/opi_ok/opi_rearm[3:0]` preserve the historical TX/A/B/BOE domains: M0..M7 require bits0..1; M8..M11 additionally require bits2..3. Output authority uses **separate** `output_gate_high`, `output_opi_ok` inputs and `output_opi_rearm` output. Fresh neutral applied-output feedback is required before IO_ENABLE, even when the provider reports no driver fault. The model raises each gate from the request after its declared delay; only then does RTL issue rearm, and only independently observed OPI feedback permits application. The output handshake must finish within500core cycles. Missing/stuck feedback or a later gate interruption inhibits application. No output domain reuses the motor BOE bit.

Inputs are `di_raw[23:0]`, `do_applied/do_fault[15:0]`, `home_raw/limit_low_raw/limit_high_raw[11:0]`, `probe_raw[1:0]`, `encoder_a/b/z/encoder_port_valid[3:0]`, and `alarm_current_raw[11:0]`. The model observes `step_out/dir_out/enable_n[11:0]`, `dout_request[15:0]`, `motion_request`, `output_request`, `permit_out_req`, `progress_m/o`, `opi_rearm[3:0]` and `selftest_state[2:0]`. Independent model feedback supplies `inhibit_n`, `wd_m_ok`, `wd_o_ok`, `gate_high/opi_ok[3:0]`, `reset_arm_ready/held`, `contactor_deenergized`, `sto_arm_expected` and `physical_safety_power_word` (labelled model observations). Watchdog self-test requires an observed fall in453000..668500 core ticks and subsequent recovery; no completion flag bypass exists.

CONFIGURE_IO page1 must precede page0. Page1 retains frozen-valid timing defaults; actual probe polarity/filter/four capture selectors are implemented. Supported selectors are M0..M11, ENC0..ENC3 and0xff. PWM duty maxima and AO maxima must be zero; those functions remain unsupported. Page0 must have all four legacy expected classes and both legacy required/critical port masks zero, output_function_mask zero, and its hash equal the motion hash. The actual provider graph directly gates I/O; zero class bytes do not fabricate card identities. `dout_enable_mask` selects the16 permissible outputs. Page0 completion sets I/O configuration validity. Every page change/rejection invalidates that status until accepted page0.

After motion CONFIGURE/SYNC and I/O configuration, execute both timed watchdog SELFTEST commands, CLEAR_CONTINUITY for re-referenced simulated channels, IO_ENABLE, then ARM. Sequence advances across both chip selects. UPDATE atomically commits twelve rates plus the DO image and one-shot arm requests. IO_WRITE works while disarmed. IO_DISABLE zeros the image. Unsupported PWM/AO/process/clear-fault payloads refuse. DO readback mismatch persisting1ms latches a fault; driver faults/provider failure inhibit outputs immediately. Any modeled limit triggers motion inhibition and a fault event; home inputs are retained provider observations, not automatic homing permission.

Probe capture and index capture enqueue actual counter snapshots in the frozen20-byte event layout. Both probes and all four index channels can enqueue in one clock. Captures are one-shot and require a new0→1 arm request. Only a matching acknowledgment for the current event head actually delivered in a complete CMD transaction pops the256-entry ring. Overflow is sticky until SYNC. No acknowledgment feeds either watchdog.
