# Global-router failures identified and repaired — 18 October 2026

The actual R3 global experiment exposed two runtime faults. These do not establish whether the complete PCB is routable without further placement or power-layout changes.

1. After the router restored a board copy, the headless progress shortcut required the old and current board identities to match. That condition ceased to hold, so progress-only whole-board statistics ran repeatedly. The fix retains the strict same-job/same-owner/headless/single-thread gate while allowing the current board copy. Initial, pass-boundary, scoring, DRC and final work stay intact.
2. The original strict-DRC recovery deserializes a replacement board, but the active pass retains Item references from the old board. Its subsequent connectivity sets mark old objects, while the new search tree uses new objects. Maze initialization then fails. The installed stock connection-routing class matches this code byte for byte. The fix resolves the queued stable ID to the current board before any connectivity query, and requires matching class, every net number, current-board membership and requested net. Missing or incompatible identities fail closed. It does not change coordinates, clearances, widths, rip-up rules, DRC or recovery.

A small control causes a real clearance violation and invokes the original strict-DRC rollback. Original code with the stale queued item fails with the same maze-creation message. Original code with the canonical current item routes successfully. The patched code routes the stale request to byte-identical final SES output; missing-ID, class and net mismatch controls reject it. Actual method-body redefinition was also tested before applying these fixes to the same live router process, without restarting it. The earlier failure counters are retained.

[Small source patch](router-runtime-two-fixes.patch) and [bounded qualification results](../evidence/router-runtime-two-fix-qualification.json) are included. The progress hunk applies to the previously instrumented headless backend; the connection-routing hunk addresses the unchanged installed class. The full runtime composition includes the earlier exact-statistics and final-output changes; this patch alone is not the complete build recipe.

The separate original-parser/no-routing/native round trip now preserves **all 94,300 source copper records including UUIDs and locks**, **all 8,015 actual via masks**, all pad groups and the same **1,693 joins / 1,719 API items**. Six exactly equivalent merged trace records were restored to their twelve original source records using integer collinear-union proofs. [Exact native preservation result](../evidence/joint-R3-exact-native-preservation.json). This proves the interchange path, not a new routing gain. The cache explanation in the [current input package](../current-global-R3/README.md) still applies.

A reusable next-pass policy also identifies 27 low-current control nets held only because existing tracks were wider than the actual 0.20 mm class requirement. They can use their unchanged domain classes for new routing; the 78 paired/precision cached joins and real power scopes retain their specific constraints. That policy will apply to a fresh post-run export rather than discarding the current run's work.

Full native routing AFTER, refill, DRC, power/return/thermal/SI, paired routing, assembly, FPGA implementation and physical qualification remain open. The existing refill and DRC processes were retained. Brief CPU readings above 80% remain recorded; continuous compliance is not claimed. No board adoption or manufacturing readiness follows.
